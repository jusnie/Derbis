Pixel — the type face

Shipped. The skin used to set three of fifteen type roles in system monospace and leave the other twelve in the default sans — 90 call sites reading as a terminal and 523 reading as ordinary type. All fifteen roles now use Pixelify Sans, bundled as two static instances. This page keeps the record: what shipped before, the four OFL candidates measured against each other at the sizes the app actually uses, and the same screens drawn both ways so the difference is visible rather than asserted.

Flips every mock on this page between today's type and the proposed face.

A settings row leaves about 250 dp for its title and a 312 dp phone about 280 dp. Press Start 2P overflows both on ordinary strings, and it is single-weight, so the Bold and Black the skin asks for would be synthesised — a fake, smeared bold, which is the one thing a pixel face must never be. VT323 is the opposite problem: single weight, a 0.56 em cap height, so every size in the app would need a ~1.25× bump to look right.

Chosen: Pixelify Sans, weights 400 and 700, on all fifteen roles — now shipped. It is the only candidate that can replace type everywhere without a reflow: its average advance is 0.524 em against ~0.50 for the font it replaces, and its cap height is 0.70 em against 0.71, so existing sizes stay honest and nothing needs re-measuring. It has four drawn weights, and two of them (400 body, 700 titles and labels) are enough for this UI — pixel type has never needed nine. Silkscreen was the runner-up: louder, more arcade, and workable for the display roles only — but it is a second file, a second licence, and it makes bold text 17 % wider than regular, so a title that fits at 400 can clip at 700.

5 — How it landed

QuestionAnswer
Bundled or downloaded?Bundled, two static TTFs in res/font, 51 KB + 51 KB. Downloadable Google Fonts need Play Services, and this repo builds an derbisFdroidBuild variant — the skin's whole identity would silently vanish on a de-Googled phone. 103 KB on a 75 MB APK is 0.14 %.
LicenceOFL-1.1 permits bundling with the licence included: assets/licenses/pixelify-sans.txt plus a REUSE.toml entry, the same way simple-icons and ionicons are handled. The face declares no Reserved Font Name, so instancing it to 400 and 700 is allowed.
Japanese, kanji, furiganaPixelify Sans has no kana or kanji (0 of 217 glyphs). Those runs fall through to the system face automatically — readable, but not pixel. A pixel CJK face does not exist in OFL at usable quality, so this is the honest limit of the approach.
Arrows, ♪, transport glyphsAlso absent from every candidate. Where those are text today they fall back; where they are icons — most of them — nothing changes, since those are Material vectors.
Other skinsUntouched. PixelTypography is only selected when DerbisActivePalette.id == PixelPalette.id, the same guard the colours already use.
Other font presetsThe Settings font picker still applies to every other skin; Pixel ignores it, exactly as it ignores corners today.
