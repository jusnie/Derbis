Update screen & the star prompt

Short answer: only half of it applies. The palette arrives on both surfaces — they turn blush and plum the moment Pixel is equipped. The type face does not: the update screen carries zero MaterialTheme.typography references across its 454 lines, so every label falls back to the system sans while the rest of the app is pixelated. And the corners are hardcoded, so the tiles and cards stay round while the big button beneath them is already square.

Below: the default look, what Pixel actually draws today, and what it draws after the fix. All three columns share one markup block — only the stylesheet differs, which is the same rule the app follows.

1 — The update screen

Every text node here is a bare Text(fontSize = …) with no style, so it inherits LocalTextStyle, which nothing in the app ever provides. Under Pixel that resolves to the system face. Column two shows it: pink, but not pixel.

5 — The fix

  1. One LocalTextStyle at the theme root, gated on Pixel. That is the actual root cause — it is also why these pages read fine while a raw Text anywhere in the app does not. Providing the pixel style fixes the update screen, the banner and every other bare Text at once, and changes nothing for the other skins.
  2. Route the hardcoded radii through one helper — pixelCorner(28.dp) returns 0 dp while Pixel is equipped and the original radius otherwise. Same treatment the lyrics page and the share cards already got.
  3. Lead the star button with the vector star, not the emoji. Strip a leading emoji from the action label when Pixel is on and let the 17 dp icon do the work, so the one coloured glyph in the skin disappears without touching the remote string.

Nothing here is implemented yet — this page is the proposal. Say the word and it lands in DerbisUpdateScreen.kt, DerbisUpdateBanner.kt, OpenSourceSupportPrompt.kt and DerbisTheme.kt.
