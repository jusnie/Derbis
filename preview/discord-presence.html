Discord Rich Presence — the lyric line and the bar

Two things the presence card now does that it did not before: it shows the lyric line being sung, and it draws a real progress bar instead of a clock that counts up. Both are live in the app — the bar comes from sending Discord the track's end timestamp as well as its start, and the lyric line rides the activity's first text slot. Everything below is derived from the shipped code, including the 60-character lyric clamp, the 128-character API limit behind it, and the 5-per-20-seconds budget.

Discord draws this card, not Derbis
No skin repaints it — a Pixel phone still shows a friend the same blurple card. The skin's input is the two text lines.

2 — The lyric line that overlapped

before · the full 128-character API limit

City lights come up through the floor and the ceiling's wrong so we dance on it till the morning comes
Hana Ito — Night Shift

Discord's details is one line in a narrow column. A 128-character lyric runs far past it, so the client either clips it mid-word or lets it crowd the second row — which is the "too big, looks overlapped" card. The old code truncated with a hard take(128), so it also ended mid-word.

after · 60 characters, cut on a word

Derbis
City lights come up through the floor and the ceiling's…
Hana Ito — Night Shift

The line now ends inside the column, the ellipsis follows a whole word, and the second row keeps its own space. The limit is one character short of 60 because the ellipsis is a character too — without that, a single unbroken word came out at 61.

SetEnd(start + duration) is what flips it to a bar. The C++ side only calls it when the duration is at least one second, so a live stream or a track of unknown length still falls back to the clock rather than drawing a bar that lies.
